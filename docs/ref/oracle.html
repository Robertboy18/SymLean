      Documentation › Oracles › oracle

      Option of #cas and cas

      oracle

      Asks SymPy, SageMath, Maxima, PARI/GP, FLINT or Gappa for a proposal, and proves it in Lean or refuses.

      #cas [mode, oracle := tool] e
      asks tool for the answer of the mode, then proves it in Lean or refuses. The modes are integrate, factor, groebner, solve, nsolve, nintegrate, eigenvalues, enclose, dsolve, sum and sos.
      #cas (digits := d) [mode, oracle := tool] e
      the same with d digits, for nsolve, nintegrate, eigenvalues and enclose.
      cas [oracle := tool]
      proves a definite integral, a membership in an ideal, an inequality between polynomials or an equation that follows from the hypotheses, from the proposal of tool. Except for a membership, it suggests a proof that needs no oracle.

      Some searches are better done by a mature computer algebra system, and I’d rather hand those to one than write them again in Lean. With oracle := sympy, SymLean asks SymPy for a proposal (an antiderivative, a factorization, cofactors, a solution, a closed form or a decimal) and then proves the statement in Lean, or refuses. Nothing the oracle says is trusted. If SymPy proposes something wrong, the proof fails, and you get a refusal instead of a theorem.

      The examples here are quoted from the oracle tests, which run with the real tools, and each output is the one that #guard_msgs pins there.

      Details and Options

      • The tools, the programs they run and their tasks:
      ToolProgramModes of #casGoals of cas
      sympySymPyintegrate, factor, groebner, solve, nsolve, nintegrate, eigenvalues, dsolve, sum, sosintegrals, memberships, inequalities, equations
      sageSageMathintegrate, factor, groebner, solve, nintegrate, eigenvalues, dsolve, sumintegrals, memberships, equations
      maximaMaximaintegrate, factorintegrals
      pariPARI/GPfactor in one variable, nsolve on a polynomial, nintegrate, eigenvaluesnone
      flintFLINTfactor, nsolve on a polynomial, nintegrate, eigenvaluesnone
      gappaGappaenclosenone
      • Nothing an oracle says is trusted. A command builds its theorem from its own input and the proposal, proves it with the checkers of SymLean, refuses a proof that uses an axiom beyond propext, Classical.choice and Quot.sound, and has the kernel check it before anything is reported.
      • A missing program, a timeout, or an answer outside the checked expression language is a refusal with the reason.
      • What can’t be checked is printed as a hint and isn’t part of the theorem: that a factor is irreducible, that a list of solutions is complete, that a Gröbner basis is reduced, that a family of solutions is the general solution. For factors with irreducibility proved, the Hex routes of #cas [factor] propose the factors and certify each one.
      • nsolve proves each root by the intermediate value theorem on an interval of width 2·10−d around the oracle’s decimal, and a root at a rational point, such as an end of the interval, by the equation at that point. The oracles compare the roots of a polynomial with the ends exactly, so that rounding does not drop such a root. The oracle finds the roots with its own numerics, which evaluate log, sqrt, real powers and quotients as complex functions, so it misses the roots that only Lean’s conventions give, such as those of Real.sqrt (x - 1/3) on [0,1/3], where Lean’s square root is 0.
      • eigenvalues proves each eigenvalue by a sign change of the square-free part of the characteristic polynomial on an interval of width 2·10−d. Two eigenvalues closer than about 10−d share such an interval and are refused, and more digits separate them.
      • An inequality is proved by a sum of squares S, found by the Gram-matrix method and made exact as in Peyrl and Parrilo 2008, Section 3.1. cvxpy finds positive semidefinite Gram matrices numerically, and we round them to rationals, project them exactly onto the linear conditions of the identity and keep them when an exact LDL𝖳 factorization shows them positive semidefinite. Lean then checks the identity with ring and the signs with positivity.
      • For 0<p, some term of S is a positive constant, or a positive constant times strict premises. When no such sum equals p, the oracle looks for a multiplier M of degree at most 2, then at most 4, such that Mp is one.
      • tests/oracle/run.sh runs one example per oracle and task with the real tools, and the edge cases of the numerical searches with SymPy and FLINT: roots at the ends of the interval and at the points of SymPy’s grid, a multiple root, and repeated and defective eigenvalues. Then it runs the same commands against programs that answer plausibly but wrongly, never answer, print garbage, answer outside the checked language, or answer with something too large to read. Every one of those is refused.

      Building#

      ModuleWhat it adds
      CASOracle.Integrate#cas [integrate x, oracle := tool]
      CASOracle.Factor#cas [factor, oracle := tool]
      CASOracle.Solve#cas [solve x, oracle := tool]
      CASOracle.Numericnsolve, nintegrate, eigenvalues and enclose with an oracle
      CASOracle.DSolve#cas [dsolve y x, oracle := tool]
      CASOracle.Sum#cas [sum k 1 n, oracle := tool]
      CASOracle.Sos#cas [sos x, oracle := tool]
      CASOracle.Ideal#cas [groebner x, y, oracle := tool] and the tactic cas [oracle := tool]
      • CASOracle is an optional library, and no module of CAS imports it. Build it with lake -R -Koracle=on build CASOracle, and lake -R build switches back.
      • Lake fetches DSLean only with -Koracle=on. An update without it drops DSLean from lake-manifest.json, and lake -R -Koracle=on update DSLean puts it back.
      • The files of CASOracle are ordinary Lean files, not modules, because DSLean’s are, so a module can’t import them.
      • The tools are needed only when a command that names one is elaborated. SymPy, PARI and FLINT run in the Python of SYMLEAN_SYMPY_PYTHON, SYMLEAN_PARI_PYTHON or SYMLEAN_FLINT_PYTHON, else SYMLEAN_ORACLE_PYTHON, else python3, with sympy (and cvxpy for sums of squares), cypari2 or python-flint. SageMath, Maxima and Gappa are the programs of SYMLEAN_SAGE_PATH, SYMLEAN_MAXIMA_PATH and SYMLEAN_GAPPA_PATH.
      • The deadline of one run is the option cas.oracle.timeout, in milliseconds, two minutes by default.

      Built on DSLean#

      We built CASOracle on DSLean, by taterowney and the DSLean contributors, released under CC BY 4.0. Its grammars write each request in the tool’s own language and read the answer back into Lean. That translation is the fiddly part of talking to another system, and I’m grateful we didn’t have to write it ourselves. SymLean requires the port in Robertboy18/DSLean, branch leancas, which updates DSLean to Lean 4.35.0 with the five changes that NOTICE lists. No DSLean file is copied into SymLean.

      Possible Issues (3)

      A nonnegative polynomial need not be a sum of squares. For Motzkin’s polynomial the oracle finds no certificate, and the refusal says nothing about the inequality:

      In[20]:=
      example (x y : ℝ) : 0 ≤ x ^ 4 * y ^ 2 + x ^ 2 * y ^ 4 - 3 * x ^ 2 * y ^ 2 + 1 := by
  cas [oracle := sympy]

      Quoted from tests/oracle/Oracles.lean, where #guard_msgs pins the output (the part shown).

      Out[20]=
      no positive semidefinite Gram matrix

      The premise x≠0 is not an inequality, so it is not sent, and without it there is no sum with a positive term:

      In[21]:=
      example : ∀ x : ℝ, x ≠ 0 → 0 < x ^ 2 := by
  cas [oracle := sympy]

      Quoted from tests/oracle/Oracles.lean, where #guard_msgs pins the output (the part shown).

      Out[21]=
      no sum of squares with a positive term

      A variable printed as x✝ can’t be written back, so the script as printed doesn’t check. The goal is still proved from the same certificate, and the suggestion is the call itself:

      In[22]:=
      theorem sos_hidden_atom : ∀ x : ℝ, 0 ≤ x ^ 2 + 1 := by
  intro
  cas [oracle := sympy]

      Quoted from tests/oracle/Oracles.lean, where #guard_msgs pins the output.

      Out[22]=

is suggested; the goal is proved from the same certificate over the elaborated atoms
